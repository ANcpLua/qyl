# qyl

qyl's Collector (api.qyl.at), the `qyl` dotnet tool, `Qyl.Api.Sdk` and the reusable `Qyl.Orchestration` process host.

Push to `main` directly; a push changing watched source/build inputs deploys the Collector (`qyl-collector`, api.qyl.at, Railway). Verify failing, new, changed and directly affected tests and the relevant build targets. Reuse passing results while their inputs stay unchanged; prose-only edits need no execution check. Do not automatically repeat whole suites for commits or releases. All `release.sh` checks remain mandatory. `mise run check` (`./eng/build.sh Check`) and `mise run check-full` are available for an explicit full check or a concrete concern; CheckFull adds the dotcov coverage gate. Without a container daemon it skips the NativeAOT smoke and SDK container stage, which run in `gh workflow run check.yml -f full=true`. Local development runs the collector as a process (`qyl up` or `dotnet run`), not in containers. The gate reports its live log immediately, then the summary and final log under `artifacts/logs/`; `QYL_VERBOSE=1` prints everything. CI runs the same gate and only reports (`.github/workflows/check.yml` on push and pull request; `weekly.yml` audits packages, runs CodeQL and checks links). Mechanical analyzer cleanup, command line only: `jb cleanupcode qyl.slnx --profile=Mechanical` (profile in `qyl.slnx.DotSettings`: redundancies, qualifiers, usings; no reformat), then `dotnet format analyzers qyl.slnx --diagnostics AL1012 SYSLIB1045 CA1865 --severity info`. Review the diff: AL1012 must not merge a `using var` into a pattern (the dispose is lost; fixed in ANcpLua.Analyzers 2.1.4), CA1822 is never applied to Fallout targets (they are instance properties), and a catch the cleanup empties gets a comment saying why (AL1309), never a dummy statement. Releases, re-pins and the contract-revision deploy order: [`SKILL.md`](SKILL.md).
