# OpenSSF Criticality Score evidence

**Score: 0.44969** (`default_score`, official implementation) · measured 2026-08-21 · threshold context: ≥ 0.40

This page exists so the score can be verified by anyone, including reviewers who
do not run code. Three independent verification paths, strongest first.

## 1. Machine-generated measurement (no code, no trust in this page)

The [Criticality workflow](../../actions/workflows/criticality.yml) builds the
official OpenSSF scoring tool and measures this repository on GitHub's own
runners. Every run's summary shows the score and all raw signals, generated by
CI, not by a human. Click the latest run to see the current number, or press
"Run workflow" on that page to produce a fresh one (any GitHub account can view;
maintainer can trigger).

The tool is pinned to the official implementation plus two collection fixes this
maintainer submitted upstream:
[ossf/criticality_score#832](https://github.com/ossf/criticality_score/pull/832).
The released v2.0.4 binary cannot measure this repository (it crashes on GitHub
App contributors such as Copilot) and reports issue counts as 0 for every
repository (the `/issues` endpoint stopped emitting the `rel="last"` pagination
header the tool relied on, verified against golang/go: reported 0 vs a true
4,034). Both bugs only ever deflate or destroy scores; the fixes restore
signals, they do not invent them. With only the crash worked around, the broken
tool reports 0.36 for this repository; fixed, 0.44969.

## 3. Reproduce it exactly (for reviewers who do run code)

```bash
git clone https://github.com/ossf/criticality_score
cd criticality_score
gh pr checkout 832
go build ./cmd/criticality_score
export GITHUB_AUTH_TOKEN="$(gh auth token)"
./criticality_score -depsdev-disable https://github.com/ANcpLua/qyl
```

`-depsdev-disable` skips an optional BigQuery-backed source that does not feed
`default_score` (the default scoring config contains no deps.dev field; this is
verifiable in the config linked above).

## Why there is no official badge or lookup service

OpenSSF publishes criticality data only as a bulk CSV/BigQuery dataset of
already-enumerated popular repositories; there is no per-repository API, badge,
or viewer (contrast Scorecard, which this repository's README badge uses). This
repository is below the star threshold for enumeration, and the production
pipeline currently runs the unfixed collector. Self-measurement with the
official implementation is therefore the only possible measurement, which is why
this page pairs the number with the machinery to verify it.
